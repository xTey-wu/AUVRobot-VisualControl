# AUV控制逻辑重构设计 v2.0

## 设计目标
大幅简化当前复杂的控制逻辑，建立清晰、可维护的控制架构。

## 初始化阶段

### 默认深度值配置
在状态机初始化时设定各阶段的默认深度值：
- **CIRCLE_KICK阶段**: `0.4m`
- **DOORFRAME_PASSTHROUGH阶段**: `[0.4, 0.3, 0.4, 0.3]` (四个门的不同高度)
- **GUIDELINE_FOLLOW阶段**: `[0.4, 0.3, 0.4, 0.3]` (根据过门数量索引)

## 各阶段控制逻辑

### START阶段
- **保持现有逻辑不变**
- 根据第一帧检测结果判断需要切入的阶段

### CIRCLE_KICK阶段 (撞球)

#### 控制策略
- **深度控制**: 全局depth_pid控制器锁定深度为 `0.4m`
- **偏航控制**: 
  - 当视野中有小球时：视觉yaw_pid控制器锁定小球
  - error = 目标x坐标 - 屏幕中心x坐标
  - 看不到小球时：yaw轴输出 `128`（中性值）
- **前进控制**: 保持定速 `155` 前进

#### 完成条件
- 小球面积连续3次大于阈值 `50000` 后的 `1.5秒`
- 满足条件后切换到 `GUIDELINE_FOLLOW` 并标注撞球完成

#### 目标丢失处理
- 继续定速定深前进直到重新找到小球

### GUIDELINE_FOLLOW阶段 (循线)

#### 最高优先级：状态切换
- **未撞球状态**: 连续3帧看到目标小球 → 切入 `CIRCLE_KICK`
- **已撞球状态**: 连续3帧看到门框 → 切入 `DOORFRAME_PASSTHROUGH`

#### 从CIRCLE_KICK进入的特殊处理
**仅当从CIRCLE_KICK阶段切入时**执行以下步骤：
1. 重置全局yaw_pid控制器
2. 立即记录进入该状态时的yaw轴角度
3. 将yaw轴角度锁定到：`当前角度 + 90度`（完成右转）
4. 向右平移 `n秒`（预留功能，当前n=0即不平移）
5. 执行完后定速前进寻找引导线

#### 控制策略
- **深度控制**: 全局depth_pid，目标值根据过门数量为索引从深度列表中确定
- **偏航控制**: 全局yaw_pid（除下置摄像头循线外）
- **循线控制**:
  - 前置摄像头看到引导线：视觉left_and_right_pid控制左右平移
  - error = 目标x坐标 - 视野中心x坐标
  - 始终保持定速前进

#### 引导线丢失处理
- **有下置摄像头**: 切换到下置摄像头对准模式
- **无下置摄像头**: 继续定速定深前进

### DOORFRAME_PASSTHROUGH阶段 (过门)

#### 控制策略
- **深度控制**: 全局depth控制器，根据过门数量锁定到目标depth
- **偏航控制**: 全局yaw_pid继续保持
- **距离控制**: 视觉forward_pid控制距离
  - 面积 > `30000`: 后退
  - 面积 < `30000`: 前进
- **对准控制**: 视觉left_and_right_pid控制左右平移对准x轴

#### 切换到ACTION_FORWARD的条件
必须同时满足以下条件并保持 `1.5秒` 以上：
- `error_x < 50px`
- `error_y < 50px` 
- `25000 < area < 35000`
- `error_yaw < 5度`

#### ACTION_FORWARD阶段控制
- **深度控制**: 全局depth_pid继续保持
- **偏航控制**: 全局yaw_pid继续保持  
- **前进控制**: 前进速度锁定 `255`

#### 目标丢失处理
- 保持低速定深前进

## 控制器使用策略

### 全局PID控制器
- `global_depth_pid`: 基于传感器数据的精确深度保持
- `global_yaw_pid`: 基于陀螺仪数据的精确角度保持

### 视觉PID控制器  
- `vision_yaw_pid`: 基于像素误差的快速偏航响应
- `vision_left_right_pid`: 基于像素误差的左右平移控制
- `vision_forward_pid`: 基于目标面积的距离控制

## 简化要点

1. **移除复杂的稳定记录器机制**
2. **简化状态切换逻辑**
3. **统一各阶段的控制策略**
4. **明确的深度管理方案**
5. **清晰的PID控制器职责分工**

## 实现优势

- **降低复杂度**: 移除不必要的过渡状态和复杂判断
- **提高可维护性**: 每个阶段的控制逻辑清晰明确
- **增强可调试性**: 简化的逻辑便于问题定位
- **提升稳定性**: 减少状态切换的不确定性
